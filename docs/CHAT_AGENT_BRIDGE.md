# VYRELON Chat Agent bridge

The Chat Agent bridge is the boundary between a conversational AI and VYRELON's executable runtime.

## Flow

    User
      |
      v
    Chat Agent adapter
      |
      | structured request/response
      v
    ChatAgentBridge
      |
      +--> VYRELON Agent Rules
      +--> WorkUnit
      +--> WorkPlan
      |
      v
    VYRELON Runtime
      |
      +--> Multi-Agent delegation
      +--> Local/Git/GitHub execution
      +--> Verify/Review/Handoff
      |
      v
    evidence + artifacts + state
      |
      v
    Chat Agent

The bridge deliberately does not give a Chat Agent direct ownership of filesystem, Git, or GitHub execution. The connected provider supplies conversation and structured intent; VYRELON remains the execution authority.

## Rule injection

Every adapter invocation receives an instruction envelope generated by build_agent_instructions(). The envelope contains the same mandatory VYRELON Agent Rules for ChatGPT, Gemini, Claude, and other providers.

This makes the rule set part of the integration boundary rather than an informal prompt convention.

## Provider adapters

Provider-specific implementations belong outside the core contracts. A ChatGPT adapter can later use an OpenAI agent/SDK integration; Gemini and Claude adapters can use their respective APIs or agent runtimes. The bridge only depends on the provider-neutral ChatAgentAdapter protocol.

The OpenAI Agents stack currently supports explicit instructions, tools, environments, and agent handoffs, which maps naturally to this adapter boundary. VYRELON should still retain authority over its own WorkUnit, policy, verification, and Git/GitHub lifecycle.
